# میوه‌چین — بازی Match-3 اندروید

یک بازی کامل Match-3 با میوه‌ها و سبزیجات، نوشته‌شده با **Kotlin** و **Canvas** خالص (بدون
هیچ کتابخانهٔ خارجی، بدون androidx، بدون موتور بازی). متاگیم و اقتصادش بر اساس همان
الگویی ساخته شده که در تحلیل APK بازی *Jewels Classic* استخراج شد
(`analysis/jewels-classic-economy-fa.md`): نقشهٔ سطح، جان و ریجن، بوستر، چرخ شانس،
مسیر ستاره (بتل‌پس‌گونه) و فروشگاه — بدون تبلیغات و بدون پرداخت واقعی.

> ⚠️ این پروژه در محیط ساخت فعلی **کامپایل نشده** است (JDK و Android SDK در دسترس نیستند).
> کد با دقت نوشته و از نظر ساختاری بررسی شده، اما اولین بیلد را باید در Android Studio
> انجام دهی؛ اگر خطایی داد، متن خطا را بفرست تا دقیقاً همان را رفع کنم.

---

## ۱. ساخت

نیازمندی‌ها: **JDK 17** و **Android SDK 34** (هر دو همراه Android Studio نصب می‌شوند).

```bash
# گزینهٔ ۱ — Android Studio
#   File ▸ Open ▸ پوشهٔ game-android را انتخاب کن، صبر کن Gradle sync تمام شود،
#   بعد Run ▶ روی یک گوشی/امولاتور (minSdk 24).

# گزینهٔ ۲ — خط فرمان (اگر gradle نصب است)
cd game-android
gradle wrapper --gradle-version 8.7     # فقط بار اول، فایل‌های wrapper را می‌سازد
./gradlew assembleDebug                 # خروجی: app/build/outputs/apk/debug/app-debug.apk
```

اگر Gradle wrapper نداری و نمی‌خواهی بسازی، Android Studio خودش هنگام باز کردن پروژه
wrapper را تولید می‌کند.

## ۲. معماری — همان چیدمان دادهٔ بازی اصلی

در APK بررسی‌شده، اقتصاد و سطح‌ها از فایل‌های داده می‌آمدند (`assets/levels/levelinfo.tsv`
و `assets/data/*.json`). این پروژه دقیقاً همان الگو را نگه می‌دارد تا تعادل بازی بدون
دست‌زدن به کد قابل تغییر باشد:

```
app/src/main/assets/
├── levels/levelinfo.tsv      # ۶۰ سطح:  id <TAB> نام <TAB> JSON
├── data/
│   ├── economy.json          # جان، ریجن، قیمت بوستر، پاداش برد، کول‌داون چرخ
│   ├── wheel.json            # ۸ قطعهٔ چرخ با وزن (احتمال)
│   ├── starpass.json         # ۳۰ پلهٔ مسیر ستاره
│   └── shop.json             # آیتم‌های فروشگاه
├── i18n/fa.json              # نام میوه‌ها
└── fonts/                    # Vazirmatn (نسخهٔ ارقام فارسی)
```

هر ردیف `levelinfo.tsv` دقیقاً همان شِمای فایل مراحل بازی بررسی‌شده را دارد
(`version`، `Area_Total[0].NewBoard`، `Candy`، `Area_Block_Create_Total`،
`Block_Kind_Count`، `Move_Count`، `levelId`، `Rank_Score`، `Target`، `mTypeColor`، `mColor`):

```
1	باغِ بهار	{"version":1,"Area_Total":[{"Order":0,
   "NewBoard":[0,56,124,254,254,254,124,56,0],
   "Candy":[[],[0,0,0,5,2,1],[0,0,3,1,2,5,1], ...],
   "Area_Block_Create_Total":[]}],
   "Block_Kind_Count":5,"Move_Count":22,"levelId":1,
   "Rank_Score":[1200,1560,1980],"Target":[[4,12]],
   "mTypeColor":[1,2,3,4,5],"mColor":[25,25,25,25,25,25]}
```

| کلید | معنی |
|---|---|
| `NewBoard` | برای هر ردیف یک ماسک ۸ بیتی ستون‌ها؛ شکل صفحه را می‌سازد (الماس، ساعت‌شنی، صلیب، هرم…) |
| `Candy` | چیدمان اولیهٔ صفحه، ردیف‌به‌ردیف؛ `0` = خالی و `1..7` = شناسهٔ میوه |
| `Area_Block_Create_Total` | خانه‌های یخی، به‌صورت `[ردیف, ستون]` |
| `Target` | هدف جمع‌آوری `[[شناسهٔ میوه, تعداد]]` |
| `Rank_Score` | سه آستانهٔ ستاره (۱/۲/۳ ستاره) |
| `Move_Count` | تعداد حرکت |
| `mTypeColor` | میوه‌های مجاز همان سطح (۵ تا ۷ رنگ) |

صفحه ۹ ردیف × ۸ ستون است و هر سطح شکل خودش را دارد؛ همان‌طور که در بازی اصلی
`NewBoard` شکل برد را تعیین می‌کرد.

ساخت مجدد همین داده‌ها (اگر خواستی بالانس را عوض کنی):

```bash
python3 tools/make-game-assets.py
```

### لایه‌های کد

| فایل | مسئولیت |
|---|---|
| `MainActivity.kt` | فول‌اسکرین، نگه‌داشتن صفحه روشن، پخش lifecycle |
| `GameView.kt` | ماشین حالت صفحه‌ها، ورودی لمس، انیمیشن برد، صدا، ذخیره‌سازی |
| `Screens.kt` | رسم خانه، نقشه، بازی، فروشگاه، چرخ، مسیر ستاره، تنظیمات و مودال‌ها |
| `Art.kt` | تمام گرافیک برداری (۷ میوه/سبزی، ستاره، سکه، قلب، آیکن‌ها) + تایپوگرافی فارسی |
| `Core.kt` | موتور Match-3، بارگذاری سطح/اقتصاد، `SharedPreferences` |

`Core.kt` هیچ وابستگی‌ای به اندروید ندارد جز `Context` برای خواندن asset، بنابراین
می‌توان منطق موتور را جداگانه تست کرد.

## ۳. مکانیک‌ها

- **برد ۹×۸ با شکل‌های متفاوت** (۸ ماسک: الماس، مستطیل، گوشه‌گرد، هرم، ساعت‌شنی، صلیب و…) و ۷ نوع محصول: توت‌فرنگی، پرتقال، لیمو، سیب سبز، انگور، بادمجان، گل‌کلم.
- **جابه‌جایی** با کشیدن انگشت یا دو ضربه روی خانه‌های مجاور.
- **سه‌گانه** معمولی؛ **چهارتایی** ← نوار افقی/عمودی (کل ردیف یا ستون را پاک می‌کند)؛
  **پنج‌تایی خطی** ← گوی رنگین‌کمان (با هر خانه که عوض شود، همهٔ هم‌رنگ‌هایش را پاک می‌کند)؛
  **شکل L/T** ← بمب (۳×۳).
- **آبشار (کمبو)**: هر مرحلهٔ ریزش ضریب امتیاز را بالا می‌برد؛ بنر «کمبو ×N» نمایش داده می‌شود.
- **هدف سطح**: رسیدن به `Rank_Score[0]` + `Target` (جمع‌آوری محصول) + شکستن یخ‌ها — دقیقاً همان سه‌گانهٔ بازی اصلی.
- **ستاره‌ها**: از روی `Rank_Score` — سه آستانهٔ صریح در فایل سطح، نه فرمول.

## ۴. اقتصاد (بدون تبلیغ، بدون پول واقعی)

- **جان**: حداکثر ۵، هر ۲ دقیقه یک جان؛ هر شروع سطح یک جان می‌گیرد. با ۷۰ سکه هم می‌توان خرید.
- **سکه**: پاداش برد = ۲۰ + ۱۵×ستاره + ۳×حرکت باقی‌مانده.
- **بوسترها**: چکش (حذف یک خانه)، برهم‌زن (چیدمان تازه)، بستهٔ حرکت (+۵ حرکت).
- **چرخ شانس**: هر ۴ ساعت رایگان؛ پس از آن ۱۲۰ سکه. جایزه‌ها با وزن در `wheel.json`.
- **مسیر ستاره**: ۳۰ پله؛ هر پله با ۲ ستاره باز می‌شود و جایزهٔ رایگان دارد.
- **فروشگاه**: بسته‌های بوستر و پرکردن جان با سکه (بدون IAP واقعی).

اگر روزی خواستی لایهٔ درآمد واقعی اضافه شود، نقاط اتصال همان‌هایی است که در تحلیل APK
دیده شد: فروشگاه (`ShopItem`)، پیشنهاد هدفمند پس از N سطح، و جایگاه تبلیغ جایزه‌ای
(اکنون هیچ‌کدام فعال نیستند).

## ۵. چه چیزی تست نشده

- بیلد Gradle و اجرا روی دستگاه (این محیط JDK/SDK ندارد).
- رندر واقعی فونت فارسی و شکل میوه‌ها روی صفحه — طرح‌ها برداری‌اند و باید یک بار چشمی تنظیم شوند.
- تعادل سطح‌ها؛ اعداد از روی فرمول تولید شده‌اند و بعد از اولین بازی واقعی باید تیون شوند.

## ۶. قدم‌های بعدی پیشنهادی

1. اولین بیلد و رفع خطاهای احتمالی کامپایل (اگر بود، خروجی Gradle را بفرست).
2. تست روی گوشی کوچک (۳۶۰dp) و بزرگ، و اصلاح اندازه‌ها در `Screens.kt`.
3. افزودن مانع‌های بیشتر (جعبه، زنجیر) — موتور برایش جای توسعه دارد (`Grid` + `Step`).
4. ذخیره‌سازی ابری و لیدربورد (فعلاً همه‌چیز محلی است).
